# API 수집 및 데이터 품질 검증 설계

## 의도

서울시 4개 물재생센터의 **유입수질** BOD, T-N, T-P를 하루 전에 예측하기 위한 데이터 기반을 만든다. 원본 API 응답과 검증용 CSV를 보존하고, 어떤 처리도 근거와 재현 기록 없이 수행하지 않는다.

## 목표

- 기본 실험 자료 기간을 2016-01-01~2026-09-30으로 고정한다.
- 서울 수질 `ViewQowRep`, 처리량 `ViewTreQty`, 기상청 ASOS `getWthrDataList` 수집 구조를 분리한다.
- 페이지네이션, 재시도, 캐시, 증분 수집, 중복 방지, 실행 기록을 지원한다.
- CP949 CSV와 API 결과를 같은 원본 구조에서 비교할 수 있게 한다.
- 센터·처리장·연도·변수별 품질 요약과 이상치 후보를 생성한다.
- 센터 통합은 검증된 규칙만 허용하고 나머지는 보류 상태로 남긴다.

## 하지 않는 일

- CSV가 없는 상태에서 사용자 제시 행 수를 검증된 결과로 주장하지 않는다.
- 처리장 수질을 근거 없이 산술평균하거나 처리량을 중복 합산하지 않는다.
- 2차 처리량을 유입유량으로 바꾸어 부르지 않는다.
- COD와 TOC를 하나의 연속 변수로 합치지 않는다.
- 모델 학습이나 성능 수치를 만들지 않는다.

## 변경된 설계

- 2006년 시작 계획을 폐기한다. 2006년 이후 통계는 연간 공표 자료이므로 일별 예측 입력에서 제외한다.
- 분할은 학습 2016~2022, 검증 2023~2024, 테스트 2025~2026-09-30을 기준안으로 한다.
- 예측은 `t`일까지 이용 가능한 정보로 `t+1` 유입수질을 예측한다.
- 14일을 기본 입력 기간으로 하고 7일·30일을 동일 평가일에서 비교한다.
- CSV는 기준 스냅샷이며 최종 수집 경로는 API이다.

## 검토한 접근법

1. **원본 보존형 API 계층 + 별도 검증 계층(채택):** 원본 재현성과 오류 추적이 쉽고, 통합 규칙을 나중에 바꿔도 재수집할 필요가 없다.
2. API 응답을 즉시 센터 일별 데이터로 집계: 단순하지만 처리장 중복과 계통 의미를 잃으므로 제외한다.
3. CSV만 사용: 현재 스냅샷 재현에는 편하지만 증분 수집 요구와 맞지 않아 제외한다.

## 구성요소

- `src/data/api_client.py`: 타임아웃·재시도·JSON 응답 검사와 비밀키 비노출
- `src/data/seoul_api.py`: 서울 API 1,000행 페이지와 총건수 기반 순회
- `src/data/asos_api.py`: ASOS 일자료 요청 인자와 응답 정규화
- `src/data/cache.py`: 원본 응답, 체크포인트, 실행 명세 저장
- `src/preprocessing/schema.py`: 원본 열과 표준 열의 일대일 매핑
- `src/preprocessing/quality.py`: 결측·0·중복·음수·극단값 후보 요약
- `src/preprocessing/integration.py`: 통합 규칙 상태 검사; 미승인 규칙은 실행 거부
- `scripts/analyze_csv.py`: CP949 CSV 분석 진입점

## 데이터 의미 보존

- 원본 `TP`는 표준 `tp_mg_l`로 매핑하지만 문서에서 원본명과 분석명을 함께 기록한다.
- `TOC(2021년 1월 이전자료는 COD)` 열은 원본 문자열과 시기 메타데이터를 보존하며 하나의 동일 물질 변수로 사용하지 않는다.
- `계통구분`으로 유입수와 방류수를 구분하고, 모델 후보에는 검증된 유입수만 포함한다.
- 처리량 1차·2차는 별도 변수로 유지하고 0과 결측을 구분한다.

## 센터 통합 상태

| 센터 | 현재 권장 상태 | 확정 전 확인사항 |
|---|---|---|
| 중랑 | 보류 | 제1~4처리장 유입수 측정 위치, 중복 여부, 대응 유입유량 |
| 난지 | 보류 | `처리장 구분없음` 유입수의 대표성, 펌프장·오니처리장 포함 여부 |
| 탄천 | 보류 | `처리장 구분없음` 유입수의 대표성, 제1·2처리장 관계 |
| 서남 | 보류 | 제1·2처리장과 시설현대화 운영기간·중복 여부 |

통합 가능성을 판정할 때 공식 대표 유입수질을 우선하고, 유량가중평균은 실제 대응 유입유량이 있을 때만 후보가 된다.

## 결측과 이상치

- 타깃 결측은 보간하지 않고 해당 타깃의 표본만 제외한다.
- 입력 결측은 원본 NaN과 결측 플래그를 유지하며 과거 정보만 사용하는 보완을 별도 실험으로 둔다.
- 강수량 결측과 0mm를 구분한다.
- IQR·MAD는 이상치 **후보**만 표시한다. 명백한 오류는 원본 대조와 처리 근거가 있을 때만 수정한다.
- 이상치 기록에는 날짜, 센터, 처리장, 변수, 원본값, 탐지기준, 판정, 처리, 근거를 포함한다.

## 보안과 공개

- `SEOUL_API_KEY`, `DATA_GO_KR_SERVICE_KEY` 환경변수를 사용한다.
- 로그·예외·실행 명세에는 키와 키가 포함된 전체 URL을 기록하지 않는다.
- 서울 원자료는 공공누리 4유형 표시를 따르므로 GitHub에 원본·변형본을 기본 포함하지 않는다.
- 코드, 빈 폴더 설명, 스키마, 취득 절차, 집계 결과의 공개 가능성은 원자료 조건과 분리해 검토한다.

## 미해결 사항

- CSV 두 파일의 실제 경로와 내용
- 서울·공공데이터포털 인증키
- 시설별 대표 유입수 측정 위치와 처리장 운영 이력
- 수질 분석 결과의 실제 이용 가능 시차
- 센터별 ASOS 관측소의 위치·기간·결측 비교
