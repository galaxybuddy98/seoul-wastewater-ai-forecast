# 예측 검증 체크리스트

`forecast-validation` 스킬을 수질 예측 문맥에 맞춰 적용한 기록 양식이다. 답이 없는 항목은 **미확인**으로 남기며 성능 주장에 사용하지 않는다.

| 항목 | 현재 기록 |
|---|---|
| 예측 계약 | 날짜×센터, 기준일 t 종료 후 t+1 유입 BOD·T-N·T-P |
| 시간 분할 | 학습 2016~2022, 검증 2023~2024, 잠긴 테스트 2025~2026-09-30 |
| rolling-origin | 학습·검증 구간 내 세부 fold는 실자료 기간 확인 후 확정 |
| 누수 검사 | shift 선행, fold 내부 전처리 fit, 테스트 모델 선택 금지 |
| 결측 처리 | 학습 fold에서만 규칙 산정, 장기 연속 결측은 기본 제외 |
| 이상치 처리 | 자동 삭제 금지, 후보 플래그와 원문 보존, 학습 기반 경계 |
| 외부 변수 | 과거 예보 스냅샷 미확보 상태. 미래 ASOS 실측 사용 시 oracle |
| 기준모델 | 지속성·전일·전주 seasonal naive, 적용 가능성 실자료 확인 |
| 지표 | 동일 평가행의 MAE·RMSE, 전체 micro·센터 macro |
| 슬라이스 | 센터·연도·계절별 표본수와 오차 |
| 과적합 | Train/Validation/Test 차이와 학습 곡선, LSTM 다중 seed |
| 재현성 | API 조회조건·수집일·원문 해시·분할·특징·seed·환경 버전 |

## 현재 판정

모델 학습 전 단계이므로 성능 판정은 **미실시**다. 실제 API 데이터와 공개 지연이 확인되기 전에는 운영 가능한 평가로 분류하지 않는다.

## 프로젝트 맞춤 차이

원 스킬의 수요·대여소·행사 관련 문구를 유입수질·센터·기상/운영 변수로 해석한다. GIS와 행사 변수는 현재 범위에 없으므로 적용하지 않는다. 날씨의 예측시점 가용성 원칙은 그대로 적용한다.
