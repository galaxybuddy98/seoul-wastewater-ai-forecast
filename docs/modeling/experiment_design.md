# 실험 설계

## 예측 계약

- 단위: 날짜×원본 처리장·유입 관측 계통(`series_id`)
- 발행 시점: 기준일 `t`의 사용 가능 자료가 확정된 뒤
- 타깃: `t+1`의 유입 BOD, T-N, T-P
- 입력 창: 7·14·30일 비교, 최종 모델은 30일
- 운영 가용성이 확인되지 않은 수질·기상 실측 입력은 후향적 또는 oracle 평가로 별도 표기

## 시간 분할

| 구간 | 기간 | 용도 |
|---|---|---|
| 학습 | 2016-01-01~2022-12-31 | 모델·전처리 적합 |
| 검증 | 2023-01-01~2024-12-31 | 특징·하이퍼파라미터 선택 |
| Test | 2025-01-01~2026-09-30 | 선택 후 참고 평가; 개발 과정에서 반복 확인됨 |

무작위 분할과 일반 KFold를 사용하지 않는다. 모델 선택은 Validation MAE만 사용했고 Test는 선택에 사용하지 않았다. 추가 검증은 미사용 기간 또는 학습·검증 범위의 expanding/rolling-origin 방식으로 수행해야 한다.

## 누수 방지

- lag·rolling은 센터와 검증된 하위 키 안에서 `shift(1)` 이후 계산한다.
- 결측 대체, 이상치 경계, 스케일러, 인코더는 각 학습 fold에만 적합한다.
- 미래 실측 날씨는 운영 성능 입력으로 사용하지 않는다. 과거 예보 스냅샷이 없으면 날씨 제외 모델 또는 oracle로 분리한다.
- 모델 비교는 동일한 평가 키 교집합에서 수행한다.

## 기준모델과 지표

Persistence를 기준모델로 사용한다. 원 단위 MAE·RMSE·R²와 Persistence 대비 MAE 개선율, 전체 및 계통·계절별 표본수와 오차를 보고한다.

## 검증 판정

`forecast-validation` 원칙을 수질 문맥으로 적용한다. 모든 입력이 발행 시점에 가용하고 테스트가 선택에 쓰이지 않은 경우만 운영 가능한 평가다. 미래 실측을 사용하면 oracle, 불완전한 데이터나 단일 분할은 탐색 결과, 미래 타깃·테스트 튜닝은 무효 비교로 분류한다.

최종 선택은 BOD `수질·기온·일강우량·계절·요일`, T-N `수질·기온·일강우량·강우 파생변수·요일`, T-P `수질·기온·일강우량·요일`의 30일 통합 XGBoost다. 실측 기상 공개 시점과 잠정 강우 관측소 매핑이 미확인이고 Test를 반복 확인했으므로 운영 확정 성능이나 완전히 독립적인 최종 홀드아웃으로 주장하지 않는다.
